= {rancher-short-name} K3k Addon
:description: The Rancher K3k add-on allows you to run Rancher as a workload on the underlying SUSE Virtualization cluster using a nested K3s cluster.
:revdate: 2026-11-17
:page-revdate: {revdate}

[NOTE]
====
*rancher-k3k* is an *Experimental* add-on. It is not included in the {harvester-product-name} ISO, but you can download the manifest (`rancher-k3k-addon.yaml`) from the https://github.com/harvester/harvester/releases[{harvester-product-name} *Releases* page]. Manifest source files are located in the `addons/standalone` directory of the https://github.com/harvester/harvester/tree/master/addons/standalone[{harvester-product-name} repository]. For more information about experimental features, see xref:introduction/document-conventions.adoc#_feature_labels[Feature Labels].
====

The *rancher-k3k* add-on allows you to run {rancher-short-name} as a workload on the underlying {harvester-product-name} cluster and is implemented using https://github.com/rancher/k3k[k3k].

The add-on runs a nested K3s cluster in the **rancher-k3k** namespace and deploys {rancher-short-name} to this cluster.

During the installation, the ingress for {rancher-short-name} is synced to the {harvester-product-name} cluster, allowing end users to access {rancher-short-name}. 

== Installing the Add-on

If you are using the {harvester-product-name} kubeconfig file, you can install the add-on by running the following commands:

=== Install k3k Add-on

[,bash]
----
kubectl apply -f https://github.com/harvester/harvester/releases/download/<version>/k3k-addon.yaml
----

=== Install rancher-k3k Add-on

[,bash]
----
kubectl apply -f https://github.com/harvester/harvester/releases/download/<version>/rancher-k3k-addon.yaml
----

Replace `<version>` with the version of your Harvester cluster (for example, `v1.10.0`).

== Configuring the Add-on

After installation, configure the add-on using the {harvester-product-name} UI.

. Go to *Advanced* > *Add-ons*.
. Locate the **k3k** add-on, and then select *⋮* > *Enable*.
. Wait a few minutes for the add-on to be deployed and marked ready.
. Locate the *rancher-k3k* add-on, and then select *⋮* > *Edit Yaml*.
. Change the fields `hostname`, `bootstrapPassword` in *valuesContent* section
+
[,yaml]
----
spec:
  chart: rancher-k3k
  enabled: false
  repo: https://charts.harvesterhci.io
  valuesContent: |-
    certManagerVersion: "v1.20.2"
    rancher:
      hostname: ""
      version: "v2.14.0"
      replicas: 1
      bootstrapPassword: "password"
    k3kCluster:
      servers: 1
      version: v1.35.4-k3s1
      storageClassName: "harvester-longhorn"
  version: 1.9.1
----

. Save changes and then select *⋮* > *Enable*. 

Once the add-on is deployed, {rancher-short-name} can take a few minutes to become available. 

You can then access {rancher-short-name} via the hostname DNS record that you provided.

See xref:integrations/rancher/virtualization-management.adoc[{rancher-short-name} Integration] for more information. 

[NOTE]
====
*rancher-k3k* is deployed on a `k3k` cluster with `{rancher-short-name}` bootstrapped as part of cluster init.

When you disable the add-on, the PVC remains in the `rancher-k3k` namespace. If you enable the add-on again, the PVC is reused and Rancher's previous state is restored.

Before you wipe the data, ensure that the PVC is deleted. 
====
