[CAUTION]
====
Do not use the embedded {rancher-product-name} instance to deploy and manage production bare-metal workloads. This embedded instance is strictly for cluster debugging and validation. You must use an external {rancher-short-name} instance to manage container workloads running on a {harvester-product-name} cluster.
====

== Rancher `harvester-baremetal-container-workload` feature flag

[NOTE]
====
This feature flag is generally available (GA) as of {rancher-short-name} v2.15.0.
====

Enabling the {rancher-short-name} feature flag `harvester-baremetal-container-workload` exposes managed {harvester-product-name} clusters as traditional downstream Kubernetes clusters within the {rancher-short-name} UI.

image::rancher/baremetal-workload-feature.png[harvester-baremetal-container-workload feature flag]

Once enabled, you can access and manage these {harvester-product-name} clusters from the following {rancher-short-name} UI locations:

* *Virtualization Management -> Harvester Clusters*
+
image::rancher/gpu-workload.png[Rancher UI - Virtualization Management - GPU workloads]

* *Cluster Management -> Clusters*
+
image::rancher/cluster-workloads.png[Rancher UI - Cluster Management - cluster workloads]

[CAUTION]
====
{harvester-product-name} manages the lifecycle of the following embedded add-ons:

* Rancher Monitoring
* Rancher Logging
* Embedded Rancher
* Embedded Fleet

These components are upgraded automatically as part of {harvester-product-name} cluster upgrades. Modifying or upgrading these add-ons manually out of band can result in cluster instability and other undesirable side effects.

RKE2 and the operating system are upgraded automatically as part of {harvester-product-name} cluster upgrades.
====

== Bare-metal GPU workloads

This configuration applies only when running a combination of virtual machines using vGPUs alongside containers leveraging physical GPUs on the same {harvester-product-name} cluster.

{harvester-product-name} leverages the https://docs.rke2.io/add-ons/gpu_operators[NVIDIA GPU Operator] for bare-metal GPU workloads.

If your cluster includes multiple GPU-equipped nodes, you can dedicate specific nodes exclusively to bare-metal container workloads by applying the node label `harvesterhci.io/gpu-baremetal-workloads: "true"`.

Applying this label disables {harvester-product-name}'s internal `SRIOVGPUDevice` management on the designated nodes and prevents `nvidia-driver-toolkit` pods from deploying to them, allowing the NVIDIA GPU Operator to take full control of the host GPU devices.

=== Sample cluster configuration

The following example uses a two-node {harvester-product-name} cluster with three physical GPUs:

* Node `hp-195` contains 2 GPUs.
* Node `hp-1992` contains 1 GPU.

. Apply the label `harvesterhci.io/gpu-baremetal-workloads: "true"` to the bare-metal GPU node `hp-1992`.
+
[,shell]
----
kubectl label node hp-1992 harvesterhci.io/gpu-baremetal-workloads=true
----
+
Applying this label removes the associated `SRIOVGPUDevices` on that node from {harvester-product-name} management.
+
[,shell]
----
(⎈|local:default)➜  ~ kubectl get sriovgpudevices
NAME               ADDRESS        NODE NAME   ENABLED   VGPUDEVICES
hp-195-000026000   0000:26:00.0   hp-195      false
hp-195-000089000   0000:89:00.0   hp-195      false
(⎈|local:default)➜  ~
----

. Apply the operand exclusion label to node `hp-195` to prevent the GPU Operator from deploying container drivers to nodes reserved for virtual machine-based vGPU workloads.
+
[,shell]
----
kubectl label node hp-195 nvidia.com/gpu.deploy.operands=false
----

. Deploy the NVIDIA GPU Operator to the cluster using a HelmChart resource.
+
[,yaml]
----
apiVersion: helm.cattle.io/v1
kind: HelmChart
metadata:
name: gpu-operator
namespace: kube-system
spec:
repo: https://helm.ngc.nvidia.com/nvidia
chart: gpu-operator
version: v26.3.2
targetNamespace: gpu-operator
createNamespace: true
valuesContent: |-
    toolkit:
    env:
    - name: CONTAINERD_SOCKET
        value: /run/k3s/containerd/containerd.sock
    driver:
    repository: registry.suse.com/third-party/nvidia
    usePrecompiled: true
    version: 595 
----

. Test GPU workload execution by deploying a sample CUDA benchmark pod.
+
[,yaml]
----
apiVersion: v1
kind: Pod
metadata:
name: nbody-gpu-benchmark
namespace: default
spec:
restartPolicy: OnFailure
# runtimeClassName: nvidia <== Only needed for v25.3.x
containers:
- name: cuda-container
    image: nvcr.io/nvidia/k8s/cuda-sample:nbody
    args: ["nbody", "-gpu", "-benchmark"]
    resources:
    limits:
        nvidia.com/gpu: 1
----
